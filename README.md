# 文本提交系统

独立于课程分组、成绩网页的学生文本提交网站。

- 学生入口：<https://ly633.github.io/text-submission/>
- 教师查看：<https://ly633.github.io/text-submission/?view=records>
- 原课程网站仍位于 <https://ly633.github.io/GDL/>，本项目不含分组、成绩页面或课程草稿功能。

学生填写姓名、学号及自由文本，无需 GitHub 账号。每次不超过 **150 字**，按 Unicode 码点计数：中文、英文字符、标点和 emoji 计数，空格与换行不计。网页和服务器均限制字数，超限后保留文字供修改，不自动截断到 150 字。

通过语义检测后才保存并返回回执，可下载回执与原文。同一学号的新观点可再次提交；网络中断后原页面原样重试不会重复保存。语义高度相似、AI 接口未配置、超时、返回格式异常时不保存。失败后页面保留输入，关闭或刷新页面不保留未提交内容。

教师使用原有密码登录，在在线表格中查看全文、加载更多记录、导出全部 Excel。姓名和学号由学生自填，尚未验证学生身份。保存的记录只允许教师读取，不发布到 GitHub 仓库；作业正文会发送至教师配置的 AI 服务进行比对，不附带姓名、学号或回执。Excel 保留学号前导零，并把用户文本写为字符串而非公式。

## 配置 AI 接口

在教师页登录，展开 **AI 接口设置**，填写完整 HTTPS 接口地址（以 `/chat/completions` 结尾）、服务商提供的模型 ID 和 API Key，点击 **测试并保存**。支持常见 OpenAI 兼容 Chat Completions 格式；其他协议需要后端适配。保存前使用两组示例验证语义判断及 JSON 返回格式。未配置前暂停学生提交。

密钥在服务器使用 AES-GCM 加密保存，只由服务器调用；查询设置不会返回密钥。密钥留空沿用，输入新值则替换；更换接口地址必须重新填写。服务器需配置运行时密钥 `AI_CONFIG_ENCRYPTION_KEY`（32 个随机字节的 Base64，勿写入仓库）。不要随意轮换此加密密钥，否则已有配置无法解密。

后台分批比较全部历史已接受作业（包括旧版长文本），将核心观点和主要论证实质相同的改写视为高度相似；同主题但论证或角度不同不应判重。完全相同的正文会直接驳回。每批要求逐项返回布尔判断，返回不完整不会放行；并发保存采用快照校验，自动补查比对期间的新提交。检测最长约 55 秒，超时可重试。AI 判断依赖所选模型，示例连接测试与自动化模拟测试不代表已验证真实课堂语义准确率。

## 网站与后台

网页源码、构建和 GitHub Pages 部署使用本仓库，独立发布。按用户要求继续使用原教师认证和保存服务；提交表与课堂成绩分别保存。旧提交记录保留，教师密码与原系统共用。页面只使用登录、退出与提交接口，不载入或修改课程草稿及成绩。

数据库与服务位于同工作区的 `classroom-backend` 项目，使用 Cloudflare D1。单个 IP 每 10 分钟最多 300 次、每学号 10 次、全局 3,000 次。教师会话仅存于页面内存，页面刷新后重新登录。

## 开发与发布

需要 Node.js 24 或 >=22.13：

```sh
npm ci
npm run dev
npm test
npm run lint
npm run build
```

本地联调可在启动 Vite 前设置 `VITE_SUBMISSION_API_BASE`。生产不设置时使用现有服务。GitHub Pages Source 选择 GitHub Actions，推送 `main` 后执行测试、构建和发布。输出目录为 `dist/`，支持 GitHub Pages 子路径。
